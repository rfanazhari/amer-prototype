## Design mapping and assessment

- `Find` reads progress, coverage, sessions, transcript, losses, handoffs and checkpoints in one
  repeatable-read, read-only transaction, then restores through `interview.RestoreProgress`.
  Corrupt state wraps `interview.ErrRestore`; absence is `ErrNotFound`.
- `Update` locks `interview_progress`, compares the progress version before any other read, runs the
  callback on a detached copy and writes only the difference in FK order (sessions, entries, losses,
  coverage, checkpoints, handoffs, progress). The version moves only after all writes succeed; a lost
  version race or unique violation is `ErrConflict`; the callback error rolls back everything.
- Explicit `Select` writes `clarification_count` 0 and null `omission_reason`, `answer_entry_id`,
  `controller_id`, `closed_at` and `summary`. No `Save`, no association autosave.
- The pinned revision and running instant are not progress columns, so a `PinReader` port supplies them
  (mock generated by `make mocks`). Trusted time comes from `service.Clock`.
- Handoff evidence, entry stage and checkpoint entry ids are derived on read from stored stage
  records; the sealed stage is immutable, so the derivation equals what the domain committed.
- The store never sees provider event names; it stores entries the caller already marked fragment or final.

Assessment: **retained with rationale**. Persistence stays in infrastructure; rules stay in the domain.

## Gaps the version 10 schema cannot hold (refused with `ErrUnmappable`, never dropped)

- Follow-up citations (`Snapshot.FollowUps`), reconnect counters, and the domain's clarification and
  omission entry ids. Consequently clarified questions and `candidate_skip` / `no_answer_after_clarification`
  omissions cannot be persisted yet. T10/T11/T13 need a forward migration or a design revision first.
- The port's "joins the lifecycle transaction carried by ctx" is not implemented: the store opens its
  own transaction. It must be wired when the lifecycle callback exists (Q3).
