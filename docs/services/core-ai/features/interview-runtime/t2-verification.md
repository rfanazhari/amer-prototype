## Design mapping and assessment

Design §1 and §4 remain the authority. `domain/interview.Progress` retains all
interview rules. Application ports declare lifecycle authority, voice transport,
and detached progress persistence. Existing candidate-interview ports are unchanged.

- `service.InterviewLifecycle`: Activate, Fence, WithProgress, Complete, Fail.
  Authority carries execution id, attempt id and expected execution version.
  Lifecycle requests contain no HR stage, question or salary fields.
- `service.InterviewDriver`: Create, Attach, Observe, SupplyContext, Control, Close.
  Session correlation retains execution, attempt, local and provider session ids.
  Create returns SDP. Observations remain opaque; no finality map is invented.
- `interviewport.ProgressStore`: Insert, Find, Update. The progress version is
  separate from the execution version. WithProgress's transaction context is joined
  by the store; the contract requires execution locking before child-row locking.
  Domain snapshots and application session/checkpoint records carry no GORM types.
- `DefaultInterviewBudgets`: 2 activation attempts, 30 seconds each in 90 seconds;
  recovery window 120 seconds, 2 replacement attempts per episode, 2 episodes.
  No post-handoff budget is invented.

Assessment: **retained with rationale**. Responsibilities are separate, aggregate
invariants stay in the domain, and the existing sibling ports need no expansion.
No design-policy change or refactor was needed. Concrete names refine the planned
unnamed signatures. Future T3/T5/T6 consumers must honor these contracts; T2 neither
supplies a real lifecycle fence nor proves database atomicity or provider behavior.
The older design's observations about absent lifecycle/schema code are historical;
this task does not reconcile those unrelated sections or clear Q1/Q2/Q3.
